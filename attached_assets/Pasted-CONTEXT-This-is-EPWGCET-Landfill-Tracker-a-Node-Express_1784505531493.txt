CONTEXT
This is EPWGCET Landfill Tracker — a Node/Express + PostgreSQL backend 
(server.js) with a React frontend, used by an Algerian public waste 
management entity. It handles client billing, personal data (Loi 18-07), 
and financial records. The director has asked for full security hardening 
before wider production rollout.

CRITICAL FINDING (must fix first)
Login (POST /api/auth/login) checks email/password with bcrypt and returns 
a user object — but issues NO session token (no JWT, no signed cookie). 
The frontend just stores that user object in localStorage and treats 
`role === "admin"` as a UI-only gate. EVERY other backend endpoint 
(/api/clients, /api/discharges, /api/users, /api/sites, /api/waste-types, 
/api/company-trucks, /api/invoices, /api/bills, /api/compliance/*, etc.) 
has NO server-side check that the caller is logged in, let alone that 
they're an admin. Right now anyone with network access to the API can, 
without any credentials:
- create/edit/delete clients, discharges, users, sites, pricing
- read the compliance audit log and breach reports
- run POST /api/compliance/purge-expired and permanently delete data
- approve/reject client conventions, change credit limits
- confirm payments and manipulate invoices/bills

FIX THIS FIRST, THEN DO THE REST BELOW.

PART 1 — REAL AUTHENTICATION (highest priority)
═══════════════════════════════════════════════════════════

1. Add JWT-based auth:
   - On successful login, sign a JWT (jsonwebtoken package) containing 
     { userId, role, siteId } with a reasonable expiry (e.g. 8-12h).
   - Return the token to the frontend; frontend stores it and sends it 
     as `Authorization: Bearer <token>` on every API call (replace raw 
     fetch calls with a small wrapper that adds this header — there are 
     many fetch() calls throughout PageGate, PageClients, PageInvoice, 
     PageOperators, PageSettings, App.jsx — find and update all of them).
   - Use a strong secret from an environment variable (never hardcoded), 
     e.g. process.env.JWT_SECRET. Fail startup loudly if it's missing 
     in production.

2. Add two Express middleware functions and apply them to every route 
   that currently has none:
   - `requireAuth` — verifies the JWT, attaches decoded user to req.user, 
     returns 401 if missing/invalid/expired.
   - `requireAdmin` — runs after requireAuth, returns 403 if req.user.role 
     !== 'admin'.
   
   Apply requireAuth to ALL /api/* routes except:
   - POST /api/auth/login
   - POST /api/users (operator self-registration — but see hardening below)
   - POST /api/users/:id/verify-email
   
   Apply requireAdmin additionally to:
   - all /api/compliance/* routes except GET /api/compliance/consent/:userId 
     and GET /api/compliance/my-data/:userId (which should instead check 
     req.user.id === :userId OR req.user.role === 'admin')
   - POST/PUT/DELETE /api/clients, /api/sites, /api/waste-types, 
     /api/company-trucks, /api/users/:id (except a user editing their 
     own profile — check req.user.id === :id OR isAdmin)
   - PUT /api/invoices/:id, POST/PUT /api/bills*, /api/bills/:id/payments
   - operator approval/rejection endpoints

3. Verify req.user.siteId matches the site being written to for 
   non-admin operators wherever site-scoped writes happen (discharges, 
   gate entries) — operators should not be able to submit discharges 
   for a site they're not assigned to, even if the frontend normally 
   prevents it.

4. Add a logout mechanism (client-side token discard is fine for JWT; 
   optionally add a short server-side blocklist for immediate revocation 
   if you want it, but not required for MVP).

5. Rotate/replace the current plaintext-in-localStorage authUser object 
   with just the JWT + minimal display info (name, role) — don't store 
   sensitive fields client-side unnecessarily.

PART 2 — NETWORK / TRANSPORT HARDENING
═══════════════════════════════════════════════════════════

6. Lock down CORS: replace `app.use(cors())` (wide open) with an 
   explicit allowed-origins list read from an environment variable 
   (e.g. your production domain + localhost for dev), using the 
   `cors` package's origin option.

7. Rate limiting: currently only /api/auth/login is rate limited. Add 
   a general rate limiter (e.g. express-rate-limit) to all /api/* 
   routes — more generous than login's, but enough to blunt scraping 
   and brute-force attempts on other endpoints.

8. Ensure HSTS, and all the existing security headers in the current 
   security-headers middleware, are also applied correctly behind 
   Render/Replit's reverse proxy — confirm `X-Forwarded-Proto` is 
   trusted (app.set('trust proxy', 1) if not already) so IS_PROD/HSTS 
   logic works correctly.
