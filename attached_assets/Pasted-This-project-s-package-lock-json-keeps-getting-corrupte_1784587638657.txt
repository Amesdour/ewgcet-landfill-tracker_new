This project's package-lock.json keeps getting corrupted with dead 
registry URLs. Several packages (vite, update-browserslist-db, 
source-map-js, yallist, side-channel, side-channel-map, 
side-channel-weakmap, side-channel-list, semver, safe-buffer, rollup, 
qs, postcss, object-inspect, node-releases, jsonwebtoken and its 
sub-dependencies, lodash.* packages, jwa, jws, ecdsa-sig-formatter, 
buffer-equal-constant-time) have had their "resolved" field in 
package-lock.json pointing to http://package-firewall.replit.local/npm/ 
instead of https://registry.npmjs.org/. This is a Replit-internal proxy 
address that does not exist outside the Replit environment.

This has repeatedly broken Render deployments: Render's Docker build 
runs `npm ci`/`npm install`, which then tries to fetch those specific 
packages from the dead replit.local address, retries 3 times over 
~71 seconds, fails, and then npm 10.8.2's known "Exit handler never 
called!" bug causes it to silently exit with code 0 anyway — leaving 
critical packages (like vite) NOT actually installed. This makes 
`npm run build` fail afterward with "vite: not found", with no clear 
error at the install step itself.

ROOT CAUSE
Whenever `npm install` or similar is run inside the Replit shell, it 
appears Replit's own environment has a registry override/proxy 
configured (likely via an environment variable like NPM_CONFIG_REGISTRY, 
or a global npm config, or Replit's own package management layer) that 
silently rewrites some or all fetched packages' resolved URLs to go 
through package-firewall.replit.local. This override does NOT appear in 
the project's own .npmrc or package.json — it's coming from something 
in Replit's environment itself, outside the repo.

     `env | grep -i registry` and show me the output
   - Any global npm config files: check `~/.npmrc`, `/etc/npmrc`, and 
     any Replit-specific config locations
   - Whether Replit's Nix/package manager config (`.replit`, 
     `replit.nix`, `.config/`) sets an npm registry anywhere
